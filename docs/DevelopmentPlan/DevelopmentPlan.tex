\section{Workflow Plan}

The team will use GitHub for version control, issue tracking, project planning,
and code review. The \texttt{main} branch will contain stable,
production-ready code, while new features and fixes will be developed on
separate branches. Each branch will address a specific GitHub Issue
and will be merged into \texttt{main} through a pull request (PR). The PR will
describe the changes, identify the linked issue, and summarize the testing that
was performed. Before the PR is merged, at least one team member other than the
author must review and approve it.

\noindent \textbf{GitHub Issues} will be used to track features, bugs, questions, and technical tasks. Issue templates will be created for common tasks such as feature requests and bug reports. Issues will be assigned to team members and linked to relevant milestones.
\\\\
\noindent \textbf{GitHub Labels} such as \texttt{feature}, \texttt{bug}, \texttt{documentation}, \texttt{frontend}, \texttt{backend}, and \texttt{AI/ML} will be used to categorize and organize issues. Priority labels such as \texttt{high}, \texttt{medium}, and \texttt{low} will be used to indicate the urgency of each issue.
\\\\
\noindent\textbf{GitHub Projects} will be used as a project board to track issues through \texttt{Backlog}, \texttt{Ready}, \texttt{In Progress}, \texttt{In Review}, and \texttt{Done} statuses. The board will be reviewed during team meetings to identify blocked or overdue work, manage dependencies, and adjust priorities.
\\\\
\noindent\textbf{Milestones} will be used to group issues according to major project phases 
and deliverables, allowing the team to track progress and identify outstanding work. 
For example, for this project milestones will likely include \texttt{MVP}, 
covering course-outline data extraction and policy checking, and \texttt{Final Release}, covering assessment conflict identification, scheduling suggestions, database exports, testing, and documentation.
\\\\
\noindent\textbf{Continuous Integration/Deployment:} GitHub Actions will be used for CI to automatically run tests, linting, and formatting checks on pull requests. Changes merged into \texttt{main} will be deployed automatically where practical.
\\ \\
\noindent\textbf{Development Workflow:}
\texttt{Issue $\rightarrow$ Feature Branch $\rightarrow$ Implementation $\rightarrow$ Pull Request $\rightarrow$ CI Checks $\rightarrow$ Code Review $\rightarrow$ Merge $\rightarrow$ Deployment}.

\section{Project Decomposition and Scheduling}

The team will use \textbf{GitHub Projects} as the primary tool for scheduling and tracking project progress. A Kanban board has been created and will be used to organize tasks into \textit{Backlog}, \textit{Ready}, \textit{In Progress}, \textit{In Review}, and \textit{Done}. Tasks will be created as GitHub Issues and assigned to individual team members. The board will be reviewed regularly during team meetings to identify blocked tasks, adjust priorities, and ensure progress toward upcoming deliverables.
\\\\
Large features will be decomposed into smaller, specific tasks that can be completed and validated within a few hours. 
\\\\
Work will be divided based on team members' skills, interests, and current workload. Team members will aim to spend approximately 10 hours per week on the project, including scheduled class time. Tasks will be distributed to balance the workload and avoid assigning too many dependent tasks to one team member. Team members will also collaborate on tasks that require multiple areas of expertise, such as integrating the frontend, backend, database, and LLM components.
\\

\section{Coding Standard}

The project will follow the following established coding standards to maintain consistency, readability, and maintainability across the codebase:

\begin{itemize}
\item \textbf{Frontend:} TypeScript and React code will follow ESLint and Prettier formatting rules.\texttt{camelCase} will be used for variables and functions, while \texttt{PascalCase} will be used for React components and types.

\item \textbf{Backend:} Python code will follow PEP 8. \texttt{snake\_case} will be used for variables and functions, and \texttt{PascalCase} will be used for classes.

\item \textbf{Database:} MongoDB documents will use consistent field naming and structure. Indexes will be used for frequently queried fields, and database operations will be separated from application logic.

\item \textbf{General:} Code will use descriptive names and consistent formatting. Comments will be used where necessary to explain non-obvious logic. Unused code and debugging statements will be removed before merging.

\item \textbf{Testing:} Backend code will be tested using Pytest and frontend code using Vitest or Jest testing library. Core functionality, API endpoints, and important application components will have corresponding tests where appropriate.


\end{itemize}
